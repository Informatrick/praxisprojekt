## Parallelization

- **Levels are barriers.** Ein Level startet erst, wenn das vorige vollständig integriert und gegen seine AC-IDs geprüft ist. So bleibt der Datenvertrag vor der UI: Logik (L1) → UI (L2) → Integration (L3).
- **`[P]` requires disjoint files.** Kein Pfad taucht in zwei `[P]`-Tasks desselben Levels auf — geprüft: T3 (page.tsx, loading.tsx), T4 (activity-suggestions.tsx, slot-card.tsx), T5 (forecast-error.tsx), T6 (datenschutz/page.tsx) sind paarweise disjunkt.
- **L1 ist bewusst sequenziell:** T2 importiert die Typen aus T1 — dieselbe Vertragskante, deshalb kein `[P]`.
- **Keine `[user]`-Tasks:** `design.md` → Settings the user makes ist leer; der `OPENWEATHER_API_KEY` liegt seit PROJ-1 in `.env.local`.
- During `/build`, each `[P]` task in the active level runs in its own subagent with an isolated git worktree, then the main agent integrates, verifies against the level's AC-IDs, and checks the boxes here. Subagents never declare themselves done — there is one verification owner.
